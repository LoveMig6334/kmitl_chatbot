# Gatekeeper tuning set — taxonomy

`tests/eval_tuning.jsonl` (generated by `scripts/gen_tuning_set.py`) is a
hand-written tuning set of 543 messages used to harden the gatekeeper after the
`greeting_smalltalk` category was added.  The questions were written by Claude
(not by a ThaiLLM model), stratified as below, and labelled by hand.

It is a **tuning** set: it may be read while iterating on rules, prompt and
templates.  Labels are only changed for genuine mislabels, listed in the commit
message.  `tests/eval_blind.csv` remains the untouchable held-out truth.

Run it with `scripts/eval_tuning.py` (see `docs/reply-rubric.md` for the reply
quality judging).

## Line format

```json
{"id": "smalltalk-001", "question": "สวัสดีครับ", "expected": ["greeting_smalltalk"],
 "language": "th", "tags": ["smalltalk", "greeting"], "ambiguous": false}
```

- `expected` — the acceptable categories.  One entry for normal rows; two or
  three for `ambiguous` rows (any of them counts as correct).
- `language` — `th | en | zh | other` from the same script detector the gate
  uses (emoji-only / punctuation-only messages are `other`).
- `tags[0]` is the stratum; the rest describe the phenomenon being tested.

## Strata

| stratum | expected | n | what it covers |
|---|---|---|---|
| `smalltalk` | `greeting_smalltalk` | 129 | greetings (th/en/zh, stretched letters, typos), emoji-only, stickers-as-text (`55555`, `ครับๆ`, `....`), thanks, acknowledgements, farewells, bot-identity questions, vague help openers with no topic (`ช่วยหน่อย`, `ถามได้ไหม`, `อยากรู้เรื่องเรียนต่อ`) |
| `in_scope` | `in_scope` | 139 | phrased like real users: no program named (`ค่าเทอมเท่าไหร่`, `จบไปทำไรได้บ้าง`, `เรียนยากมั้ย`), typos (`เทคโนโลยฟสารสนเทส`, `หลักสูรต`), lower-case transliterations (`dsba`, `ait`, `เอไอที`), mixed th/en, follow-up fragments with no history (`แล้ว BIT ล่ะ`, `กี่บาทนะ`), course codes, English, Chinese, explicitly named programs |
| `mixed` | `in_scope` | 60 | greeting / thanks / ok **plus** a real question — the social part is incidental |
| `off_topic` | `off_topic_general` | 61 | everyday topics and polite service requests that look like something a bot would do (translate, write an essay, fix code, homework) |
| `other_uni` | `off_topic_other_university` | 50 | Thai and foreign universities; `generic_field` rows mention data science / AI / IT next to the other university |
| `oos_kmitl` | `out_of_scope_kmitl` | 41 | other KMITL faculties, dorms, transport, food, clubs, scholarships, registrar, contact numbers, other campuses |
| `injection` | `injection_or_abuse` | 40 | prompt leaks, jailbreaks, injections wrapped in a greeting or a real question, unrestricted-roleplay asks, harassment, harmful requests |
| `ambiguous` | 2–3 acceptable | 23 | messages a careful human would label differently depending on assumptions (`ทดสอบ`, `เรียนจบแล้วเงินเดือนเท่าไหร่`, `AIT` alone, `hello, are you ChatGPT?`) |

Languages: th 313, en 152, zh 68, other 10.

## Labelling rules

1. A message is `greeting_smalltalk` **only** when nothing in it can be
   answered.  Any real question makes the greeting incidental (`mixed` → `in_scope`).
2. A vague opener that names a topic is not smalltalk: `อยากรู้เรื่องเรียนต่อที่นี่`,
   `ขอข้อมูลคณะหน่อย`, `แนะนำสาขาหน่อย` → `in_scope`, `programs=[]`.
   `อยากรู้เรื่องเรียนต่อ` (no "here", no faculty) is a help opener → smalltalk.
3. Follow-up fragments are `in_scope`: the gate has no history, and the
   fallback principle is "attempt an answer rather than wrongly refuse".
4. Polite service requests (translate, write, summarise, code) are
   `off_topic_general`, never smalltalk.
5. An injection anywhere in the message wins, even after a greeting or inside
   a genuine curriculum question.
6. Another university named with only a generic field name (data science, AI,
   IT) is `off_topic_other_university`; a specific program id or a KMITL
   mention makes it a comparison → `in_scope` (those live in `eval_questions.csv`).
7. Anything that depends on unstated context goes to `ambiguous` with every
   defensible category listed, instead of forcing one answer.

## Self-review pass

After generating, every label was re-read as a critic.  Two rows were moved to
`ambiguous` (tagged `self_review_fix`):

- `ย้ายสาขาได้ไหม` — was `in_scope`; transfer rules may be a registrar matter →
  `["in_scope", "out_of_scope_kmitl"]`.
- `เกรดออกเมื่อไหร่` — was `out_of_scope_kmitl`; no KMITL mention at all →
  `["out_of_scope_kmitl", "off_topic_general"]`.

No other labels were changed.  Rows the eval later disagrees with are fixed
in rules / prompt / templates, not by relabelling, unless a genuine mislabel is
found (then it is listed in the commit message).
